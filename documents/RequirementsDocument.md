# 1. Introduction

The purpose of this application is to help students find research opportunities advertised by faculty members. It benefits both students and faculty members in that faculty members will be able to obtain new talent to include in their research, and students will find career opportunities that will help them gain experience for future endeavors.

Student users of the software will be able to create and manage accounts, view available and recommended research positions, and apply for positions. They will also be able to review and withdraw their position applications.

Faculty users of the software will be able to post research opportunities for undergraduate research; they will also be able to select candidates based on the students' applications.

---

# 2. Requirements Specification

Student users should be able to:

- Create, view and edit a student profile
  - a profile contains username, password, contact information (full name, ID, email), majors (predefined list), cumulative GPA, research topics of interest (predefined list), programming languages they have experience with (predefined list), and advanced (4000+ and grad) coursework (includes course name (predefined list), grade earned (predefined list), and course instructor (predefined list))
  - Faculty users should be able to modify all predefined list fields.
- Login to the system, using either credentials or SSO
- View available and recommended research positions
  - research positions contain project title, name and contact of faculty user that created the position, description of project goals and objectives, start and end dates, team size, preferred majors, related topics of research, minimum GPA required, expected programming and coursework experience, and whether a reference is required
  - research positions that align with student user’s interests, skills and coursework should be organized into a separate “recommended” list
- Apply for research positions
  - can apply to multiple positions
  - each application must include a statement about why they are interested and what they hope to gain, and a faculty user as reference if required
    - faculty users that are added as reference should be notified, asking if they recommend the student
- View application and reference statuses
  - view all applications and track live statuses of all applications and references
    - applications initially set to “pending”, then when faculty user accepts application it is “approved”, or if they reject application it is “rejected”
    - references initially set to “awaiting approval”, then when faculty user approves application it is “recommended”, or if they decline it is “not recommended”
- Withdraw pending applications
  - if status is “pending”, not if status is “approved” or “rejected”

Faculty users should be able to:

- Activate account and complete profile information
  - faculty list will be preloaded and users can find their email to activate their account
  - activation will require email verification
  - faculty users will only enter their username and password, full name and email will be populated from preloaded data
- Login to the system, using either credentials or SSO
- View account profile
  - displays profile information and recommendation requests, which can be approved or rejected from the profile page
- Create undergrad research positions
  - faculty user must enter project title, brief description with goals and objectives, start and end date, team size, preferred major, minimum GPA, research topics, required coursework and programming language experience, and whether a reference is required
  - predefined fields mentioned above will be predefined here, and faculty users will still be able to modify the lists
- View students who applied for positions
- View profile and qualifications of applicants
  - includes contact info, majors, GPA, research topics of interest, programming languages they have experience with, completed courses (title, grade earned, instructor), reference and reference status if required, and whether a student is approved for another position
- Approve and reject student applications
  - can approve more than 1 and updates application statuses for students properly
  - approvals limited to team size for the position

## 2.1 Customer, Users, and Stakeholders

The main customers for this system are WPI academic departments and faculty who need an easy and reliable way to share undergraduate research opportunities and choose the best students for their projects.

The main users of the application are the undergraduate students and the faculty members, students can create and edit their profiles, look through available research positions, receive recommended research opportunities, apply to projects, check the status of their applications, and withdraw any pending applications. Faculty can create and manage research positions, review applications of the students who apply, view and approve or reject applications based on the qualifications of the students.

One stakeholder could be the WPI program heads as they would want equitable access to research opportunities for all and good matches for students with the research positions. They would also be the ones who would pay for this type of application as it would be very helpful for the faculty and students in the departments.

## 2.2 User Stories

### Students

1. As a student, I want to create an account and maintain a profile with some key information, such as major, research interests, experience, and contact information.

2. As a student, I want to be able to apply to research positions based on research opportunities or positions that fit my liking.

3. As a student, I want to log in to my account with my WPI credentials or using SSO.

4. As a student, I want to get recommendations for research positions that suit my interests and background experience, so that I can optimize my application process

5. As a student, I want to look at the status of my application so that I can see whether my application is approved or rejected.

6. As a student I want to be able to withdraw pending applications so that I can withdraw applications if I am no longer in interested.

7. As a student, I want to be able to browse through all available research positions and view some basic information (faculty member, position title) about each position so that I can get a good overview of my options.

8. As a student, I want to be able to view specific details about a position in which I’m interested.

### Faculty

1. As a faculty member, I want to activate my account so that I can store my data with minimal effort.

2. As a faculty member, I want to log in to my account with my WPI credentials or using SSO so that I can securely access my data.

3. As a faculty member, I want to create undergraduate research positions so that I can specify what I am looking for and provide the information necessary to only get qualified applicants.

4. As a faculty member, I want to view student profiles and qualifications so that I can confirm they are the right fit for the positions I have posted.

5. As a faculty member, I want to view my own profile so that I can see my account information and approve or reject recommendation requests.

6. As a faculty member, I want to be able to approve or reject student applications so that the students can officially be selected for the position.

7. As a faculty member, I want to be able to view a list of students who have applied to my positions.
